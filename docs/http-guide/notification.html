CHAPTER 05 / 06

发现有货后，消息怎样到手机？

查库存是 Mac 发给 Apple 的 GET；发 Telegram 是另一条发给 Telegram 的 POST。两者是不同的 HTTP 请求。

有货时，会发生另一组 HTTP 往返

Mac 监控
GET · 两个 SKU + 邮编 →
Apple
← 200 + JSON 库存结果
Mac 监控
POST · sendMessage →
Telegram API
← { "ok": true, ... }

Mac 验证库存、取货日期和重复提醒规则后，才向 Telegram 发出请求。Telegram 接收后，再由它的服务把消息送到你的手机；这是 Telegram 的投递链路。

Telegram Request 长什么样？

下面完全使用占位符。网页不包含真实 Bot Token、Chat ID 或你的个人资料。

POST 示意 · 与查询 Apple 的 GET 不同
POST /bot<BOT_TOKEN>/sendMessage HTTP/1.1
Host: api.telegram.org
Content-Type: application/x-www-form-urlencoded

chat_id=<CHAT_ID>
&text=<URL编码后的提醒文字>
&disable_web_page_preview=true

这里为了便于阅读把 body 换行；真正发送的是一段用 & 连接的表单字符串。

Telegram Response · 教学示意，result 的其他字段省略
{
  "ok": true,
  "result": {
    "message_id": 123,
    "text": "📱 iPhone Duo 可 Pickup …"
  }
}

程序收到 ok: true 后，才把这次提醒记入本地去重记录。发送失败时不会提前标记为“已经通知”。API 接收成功，也不等于你已经看到手机上的消息。

为什么发送更及时了？

每个区域响应解析完成后，匹配的库存就立即通知，不会等另一个区域查询结束。平时同一轮的第二个区域，会在第一批处理完后再等至少 5 秒才发请求。

浏览器自动打开算什么？

Telegram 成功发送后，程序调用 Mac 的 open，打开对应颜色和容量的商品页。浏览器随后自行加载网页，会产生另外的页面和资源请求。

它不是另一次库存轮询，也不会自动选择门店、下单或支付。每轮每个型号最多打开一次。
