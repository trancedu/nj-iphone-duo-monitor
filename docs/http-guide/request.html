请求怎样写，Apple 才知道查什么？

一条 URL 同时带上一个邮编、两个型号；35 家店是本地目标名单，不是 URL 中的 35 个参数。

动手组装一个 GET 请求

这里的变化只更新示例文字；没有调用 Apple 接口。每次真实请求都包含固定的白色 256GB。

MK1E4LL/A · 白色 256GB
GET → www.apple.com:443
完整 URL · 可复制查看


HTTP/1.1 文本示意 · HTTPS 实际线上为加密传输
示意中只展示关键头。Host 等由网络库补充，底层连接头未完整列出；此处不是抓包导出。




逐项拆开 URL
部分实际值含义
Schemehttps://使用加密连接。
Hostwww.apple.com请求发送到 Apple 的域名。
Path/shop/retail/pickup-message本程序当前使用的取货查询接口。
Querypl=true沿用查询接口的固定参数；它不代表“有库存”。
Querylocation=07078以这个邮编作为附近门店的查询中心。
Queryparts.0=MK1E4LL%2FASKU 编码对应白色 256GB。%2F 是斜杠 / 的 URL 编码。
Queryparts.1=另一个SKU第二个颜色、容量组合；两个型号合在同一请求中。


没有“每家店再发一个请求”。
本地保存 35 家目标店号。Apple 按邮编返回附近一组门店，程序从中筛选目标店；店号主要出现在响应和本地配置里。


发送这条请求之前，Python 做什么？
  1. select_products() 选择白色 256GB 与随机另一个型号。
  2. select_regions() 选择本轮一个核心区与一个外围区。
  3. inventory_region() 用 URL 编码拼接参数，调用网络库的 open()。
  4. 当前请求最多等待 25 秒；HTTP 错误或网络异常会转为查询失败，进入退避。
库存查询没有请求正文（body），参数都在 URL 中。它也没有附带你的付款信息或浏览器登录 Cookie。
