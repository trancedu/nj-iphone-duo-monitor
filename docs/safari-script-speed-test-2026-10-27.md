## 实跑发现并修复

Apple 对有货产品可能自动预选门店/日期，原先 `standbyState` 把默认值误当作正在操作而停止。现在只有在脚本从已验证购物袋新建 Checkout，或从已标记待机页刷新后，才允许设置待机标记。脚本显式选店后立即进入保护状态；原生用户改变门店/时间也撤销待机资格。未知的既有已选页面不自动冒认待机页，显式测试重置必须用 `--return-to-standby`。

### 网络、渲染和本地操作如何区分

第二轮关键 `/shop/checkoutx/fulfillment` 请求从页面相对时间 4608 ms 到 12489 ms，共 **7881 ms**，首字节在 12489 ms 才到，响应体下载在 Safari 的毫秒精度下接近 0 ms。对应 Node 等待联系人页 8333 ms，其中约 **94.6%** 可由这个请求覆盖，响应结束后约 452 ms 才观察到联系人表单。该 452 ms 包括页面更新、轮询等待和 AppleScript 传输，不能全部叫作渲染。

第一轮同一个请求约 **4393 ms**，而等待联系人页 4883 ms。两轮都有明确的服务器/网络响应等待证据；此前未采集 Resource Timing 的 15.411 秒不能事后精确拆成网络和渲染。

第二轮初始 Checkout 文档 TTFB 441 ms、下载 18 ms；响应结束后约 251 ms 到 `domInteractive`，269 ms 到 `DOMContentLoaded`。这只能描述文档解析/脚本就绪阶段，不等同于所有 React 更新、布局和绘制耗时。第三轮未开启请求诊断，不虚构它的网络分项。

诊断轮的 DOM 函数本体合计仅 **56 / 81 ms**；AppleScript 调用往返合计约 **7.73 / 11.02 秒**，调用次数 **42 / 58**。往返总时间包含 Safari 排队、脚本执行与轮询期间等待，且与网络请求重叠，**不能把网络时间与往返合计再相加**。单次 AppleEvent 往返通常约 0.15–0.2 秒，因此减少无意义往返比微调 DOM 算法更有价值。慢网络会增加轮询次数。

### 已实施的统一修复/优化

- 仍用同一个 `prepareSafari`，iPhone 18 只是测试 URL；生产继续选择事件指定门店，测试才选首个可用门店。
- `--require-standby` 先确认已在自提＋07094，再进入 `started_at`；错误起点直接停止，不把重建购物袋伪装成自提页开始的耗时。
- 刷新后用同一次小状态读取判断新文档、自提、ZIP 编辑状态、过期/保护状态，移除多次完整 snapshot/重复检查；不等无关图片全部加载完才继续。
- 已选中的日期不重复点击；一次读取同时获取日期和时间候选，减少往返。
- 门店按稳定 Rxxx ID 选择，兼容 Apple 后补距离、文案变化；没有 ID 的夹具保留唯一名称匹配。
- `Available Windows` 占位项不算时间；选时间后必须读回正确值。继续前再次验证时间、日期和门店 ID，避免表单异步重置后误点下一步。
- 有区域无货提示不展开；没有提示才展开。保留 ZIP 无法验证时的纠正，不为了快假定城市名称就等于所需邮编。
- 生产不开 `--trace`，无额外性能采样。最终 Apple Pay 严格点一次，不重试不确定的付款点击，不自动取消。

### 仍可改善但本轮没有冒险跳过

联系人页后台请求是本轮最大波动，无法靠减少 DOM 读取保证其永远变快；绕过选店/时间服务器校验或重复发送会引入错误。ZIP 显示变成城市时，纠正会再花约 1.3–1.4 秒，不能仅凭物理城市相同就跳过。继续减少往返可以考虑更大的页面内状态机，但需要额外评估断页/重启/人工接管和动作去重；本轮没有另写一套与生产分叉的抢购脚本。

### 最新门店展开与选中规则

待机和刷新本身不再自动展开全部门店。出现可见的 `There's no availability within your location. Please try another search.` 时不展开；生产流程仍须使用事件指定门店。目标门店已经可见且可选时，直接验证并选择它，再等待日期及时间窗口；若 radio 已被自动选中，只校验，不重复触发点击，同时仍设置页面保护标记。仅在目标隐藏或未列出、且没有明确区域无货提示时尝试展开。时间窗口仍按当前页面有效选项选择第二个，并在继续前核验，避免异步更新重置选项。

### 门店选择统一为首个可用（最新覆盖规则）

按用户确认，Safari 正式事件和测试都使用页面 DOM 顺序中的首个 enabled 门店，不再限定为通知中的门店。通知门店保留在诊断上下文中，用于解释触发来源；实际选中门店仍按稳定 ID 校验。已选中则复用，随后选择第二个有效时间窗口。`pickup_first_available_store` 默认 true，正式适配器显式启用；false 仅保留给指定门店诊断回归。

### 本机模拟库存信号端到端测试（2026-10-28 美东）

使用隔离的 PickupTest18Pro 窗口和独立状态目录，以随机鉴权密钥向本机临时 HTTP 接收器 POST 到货事件，经过正常 ProfileRouter、Engine、SafariPickupBrowser 及共享工作流。正式四窗口接收器未接收这些测试事件，测试禁止 Apple Pay 最后点击。

修正：待机 arm 把真实选中/钱包/联系人页保护与尚未加载完成分开。缺少 fulfillment 标题、商品或门店列表时返回尚未就绪，等待后重读；已选门店/付款标记仍立即停止。两个针对加载重建的回归及待机套件共 23 项通过。修正后再测：信号到就绪 4.794 秒，received_at 到就绪 4.391 秒，收到后 0.541 秒请求刷新、2.921 秒验证门店、3.272 秒选好时间。两次成功均选 Apple American Dream、第二个有效时间段，未点击 Apple Pay。
