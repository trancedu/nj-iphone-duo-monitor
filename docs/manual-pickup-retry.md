# 手动控制自提重试

桌面提供两个入口。先在 Safari 选中要处理的正式窗口，再双击脚本。脚本按 Safari 当前选中窗口的 Profile 精确识别 A–F 六种配置；若当前是测试或其他窗口，会显示六种配置供选择，绝不会操作个人或测试窗口。

- `立即重试自提.command`：安全结束选中配置的旧流程，恢复到 I’ll pick it up，然后立即刷新重新找库存。有货就按正式流程继续到 Apple Pay，由用户完成付款认证；没有货按现有有界策略退出。
- `仅恢复自提.command`：结束旧流程并恢复自提待命，不主动启动一轮重查。后续真实库存事件照常接收。

这两个入口不停止或重启接收服务，不恢复其他五个窗口。已经在正常自提页时不先回购物袋，也不额外导航；立即重试模式随后由正式流程执行它的库存刷新。紧急操作接受现有 07094 或 East Rutherford 显示，不为了改邮编拖延；正常空闲维护仍设置 07094。

## 运行方式

在桌面双击。也可以直接指定配置，适合绑定 macOS 快捷指令的“运行 Shell 脚本”：

```sh
/opt/homebrew/bin/python3 /Users/trance/coding/iPhoneDuo/deploy/retry_pickup.py --profile B
/opt/homebrew/bin/python3 /Users/trance/coding/iPhoneDuo/deploy/retry_pickup.py --profile B --restore-only
```

配置：A 256GB 白，B 256GB 黑，C 512GB 白，D 512GB 黑，E 1TB 白，F 1TB 黑。

`--dry-run` 只显示目标和模式，不发送请求、不操作页面。

## 行为和保护

本机调用经过身份验证的 `/retry` 接口，服务端还要求 loopback 来源、明确模式和预期的旧任务 ID。若双击后恰好有新任务接管、任务 ID 已变化，操作会拒绝覆盖新任务，并提示重新操作；不是拿旧快照清掉新单。重复点击尚在恢复中的配置只返回同一任务，不会并行操作。

旧浏览器脚本在运行时先标记取消、等待它安全退出，再恢复页面，不能用两个脚本竞争点击。恢复准备期间新的同款请求暂存，其他配置独立运行。旧的排队候选作废。用户主动重试是一次新的本机库存重查，不是宣称监控 API 发现了新库存；仍需重新读取页面实际可用门店和时间。

准备失败时记录具体状态，不标成恢复成功；脚本不重复发送付款或重试命令。终端显示中文结果。付款是否实际弹出以 Safari 为准，`awaiting_user` 状态本身不能证明原生 Apple Pay 面板已经出现。

脚本只引用本机程序路径，凭据从既有私有文件读取，不写入桌面脚本。手动按钮是用户主动放弃旧流程的操作，可能打断正在处理的付款；它不代表旧订单一定失败，付款结果需要用户自行确认。
